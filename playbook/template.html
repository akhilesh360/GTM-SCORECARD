1Executive summary

Two portfolio companies sell in different ways: Acme MSP wins managed-IT contracts mostly from inbound search, and Summit HVAC wins commercial service work mostly through outbound and the phone. This system measures both on one set of definitions, automates lead handling, and documents everything a GTM Engineer needs to run it and roll it out.

4Attribution and financial logic

Every metric has one definition, written once in code and applied to every company. The definitions below are the contract; if a company reports a number that doesn't match them, it isn't the scorecard number.

{{metric_defs}}

Attribution models

  • First-touch: 100% of a won deal's amount to the first touch. Answers "what creates demand?"
  • Last-touch: 100% to the last touch before the deal was created. Answers "what converts demand?"
  • Linear: equal split across every touch up to deal creation. The default for budget discussions, because no single touch gets all the credit.

Design decisions. (1) Opportunities count deals that reached Qualified, even if later lost; filtering on the current stage undercounts opportunities and inflates win rate. (2) CAC includes the fully loaded outbound team cost, referral payouts and call-tracking fees, not only media, so channels compare fairly. (3) Pipeline velocity uses the standard formula (opportunities × win rate × ACV ÷ cycle days), in dollars per day. (4) Customer lifetime is a per-company assumption from churn, set in config and shown on the scorecard.

7Rolling out to a new company

The success test: a new company needs only its data inputs and its pipeline names. This was checked by adding a third test company with nothing but a new config file; the scorecard, dashboard, HubSpot files and agent routing all picked it up with no code change.

  1. Config. Copy a company file to config/companies/<slug>.json; set pipelines and their routing rule, territories and owners, ICP, customer lifetime and Slack channel.
  2. Data. Export the seven standard files into data/<slug>/, mapping source channel names onto the five standard channels.
  3. HubSpot. Run python -m gtm.hubspot setup --apply to add the pipelines and dropdown values, then import.
  4. Run. python run_all.py --skip-generate. Review the data-completeness section first; fix gaps at the source before trusting CAC.
  5. Agent. Point the company's HubSpot webhook at the agent; watch the first 20 leads in Slack.

8GTM Engineer onboarding

One GTM Engineer can own this system across the portfolio. The role sits between RevOps, marketing ops and data: they keep the standard intact, keep the data clean, and roll the system out company by company.

Hiring profile

  • 3+ years in RevOps, marketing ops or growth engineering
  • HubSpot admin depth: properties, pipelines, workflows, imports, private apps
  • SQL and Python fluent enough to own gtm/model.py
  • Has built at least one webhook or API integration
  • Can explain CAC payback to a CFO and a lead-routing bug to a rep

Interview exercise

Give the candidate this repo and one company's messy export. Ask for the scorecard in 3 hours and a list of the data problems found. Score on definitions held, problems surfaced and clarity of the write-up.

First 90 days

Days 1–30: own it. Run the pipeline end to end; reproduce every scorecard number by hand for one company; rotate the HubSpot token; fix the top three data-completeness gaps.

Days 31–60: make it live. Agent on live webhooks for both companies; scheduled daily run with Sheets sync; first monthly scorecard review with each company's GTM lead.

Days 61–90: propagate. Onboard a third portfolio company using Section 7; replace mock enrichment with a real provider; propose the first budget shift backed by linear attribution.

Troubleshooting

SymptomLikely causeFix

Assumptions and limits

  • All companies, people and records are synthetic. Generator inputs match the design targets; realized rates differ slightly because deals still open at the cut-off are not yet won or lost.
  • Revenue is closed-won first-year contract value. LTV uses ACV × margin × lifetime; it ignores expansion and discounting.
  • Enrichment is mocked. HubSpot, Slack, OpenAI and Google Sheets clients are written against their public APIs but were exercised in the POC only against mocks.
  • In production, add retries and a dead-letter queue to the agent, store secrets in a secrets manager, and move SQLite to the portfolio warehouse.
